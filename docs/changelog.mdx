<Update label="v0.7.0" description="September 2026">
- **Blog categories**: opt-in category pages backed by published tags, with topic metadata, linked badges, URL pagination, canonical/social metadata, sitemap entries and server-rendered 404s
- **Hardening**: opt-in strict docs/blog build validation (missing/duplicate pages, broken internal links, unsupported frontmatter), an accessible native search dialog with keyboard navigation, page metadata kept current across client navigation, and HTTP 404 + noindex for missing docs and posts when server rendering
- **Breaking — grammars are per-language features**: `highlight` alone compiles only Rust; `lang-bash`, `lang-css`, `lang-dockerfile`, `lang-html`, `lang-javascript`, `lang-json`, `lang-markdown`, `lang-python`, `lang-toml`, `lang-typescript` and `lang-yaml` are on by default, while `lang-c-sharp`, `lang-cpp` and `lang-tsx` are off. A fence without a compiled grammar renders as plain text
- **Breaking — `openapi` feature**: spec parsing (`with_openapi()`, `<OpenAPI>` blocks) sits behind an on-by-default feature; `default-features = false` builds must add it
- **Breaking — no leaked dioxus features**: the kit no longer enables `launch`, `logger` or `devtools` on your `dioxus` dependency, and `DocFrontmatter` / `BlogFrontmatter` no longer derive `Deserialize`
- **Smaller bundles**: frontmatter no longer needs `serde_yaml`, `openapiv3` is optional, and this site's wasm went from 25 MB uncompressed to 1.4 MB brotli (7.2 MB raw). Build with `dx bundle --web --release --debug-symbols false` to get the same
</Update>

<Update label="v0.6.1" description="August 2026">
- **Precompiled stylesheet**: `dioxus_docs_kit::DOCS_KIT_CSS` ships every class the kit's components emit, so a Tailwind toolchain is optional
</Update>

<Update label="v0.6.0" description="August 2026">
- **Parser hardening**: no crashes on malformed or non-English input, no content dropped from fenced code blocks, `~~~` fences and headings inside fences handled correctly, tags and attributes matched exactly
- **`use_docs_context()`**: builds a `DocsContext` with a reactive current path
- **Performance and correctness**: ~7x faster parsing, search results capped at 25, valid XML in RSS and sitemaps, correct sidebar in server-rendered HTML
- **MSRV 1.88**
</Update>

<Update label="v0.5.0" description="July 2026">
- **SeoRouter (server feature)**: One builder generates all crawler endpoints — per-page raw Markdown, `llms.txt` / `llms-full.txt`, sitemaps, blog RSS, and robots.txt with per-AI-crawler entries
- **Context constructors**: `DocsContext::new()` / `BlogContext::new()` with defaulted meta fields — new fields no longer break consumer builds
- **Better errors**: `try_build()` on both config builders; OpenAPI/nav parse errors now surface the underlying line/column detail instead of a generic panic
- **Multi-spec OpenAPI fixed**: Sidebar links and endpoint pages now use the spec that owns each operation
- **Blog search theming**: The blog search modal shares the docs modal shell and picks up the `dk-search-*` classes
- **Performance**: Precompiled regexes, precomputed API sidebar entries, and O(1) operation lookup
- **Fixes**: Windows path handling in `dioxus-docs-kit-build`, malformed frontmatter no longer renders as page text, blog posts with invalid frontmatter warn instead of vanishing silently, scroll/keyboard listener leaks fixed
- **Theming Surface**: `DocsVariant` API with built-in presets — shadcn light/dark, brutalist, and default
- **SEO Meta**: Auto-generated `<title>`, description, OpenGraph, and Twitter card tags from frontmatter
- **Compile-time Blog Engine**: Featured posts, related posts, and a scroll progress bar
- **Mermaid Diagrams**: ` ```mermaid ` fenced blocks render as interactive diagrams
</Update>
